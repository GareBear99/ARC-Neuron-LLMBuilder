This repository is prepared for discoverability, but search engines index public pages only after the repo is pushed, GitHub Pages is enabled, and crawlers revisit the site. This document gives the exact public-facing checklist.

## GitHub Pages

Enable GitHub Pages from the main branch. The repo already contains:

- `_config.yml`
- `index.md`
- `robots.txt`
- `sitemap.xml` support through `jekyll-sitemap`
- JSON-LD metadata in `docs/seo_metadata.jsonld`

## Release SEO checklist

For each release:

1. Use the release title format: `ARC-Neuron LLMBuilder vX — Governed Local AI / GGUF Candidate Pipeline`.
2. Include the honest status line first.
3. Include benchmark counts and incumbent status.
4. Include five use-case bullets.
5. Link README, PROOF, QUICKSTART, and production handoff docs.
6. Add a changelog section with exact changed files.

## External indexing checklist

After pushing:

1. Submit the GitHub Pages URL to Google Search Console.
2. Submit the GitHub Pages URL to Bing Webmaster Tools.
3. Add the repo to the TizWildin / GareBear99 hub site.
4. Link it from ARC-Core, Arc-RAR, Omnibinary, Cleanroom Runtime, and arc-language-module READMEs.
5. Create a short demo video or post titled around `local AI model builder with rollback receipts`.
6. Post release notes on GitHub Discussions.

## What not to claim

Do not claim:

- Claude-level capability,
- Gemma-scale trained checkpoint,
- medical/therapy-grade safety,
- guaranteed autonomous learning,
- or production frontier model status.

Correct wording:

> production-candidate governance loop for local model growth, benchmarked candidates, provenance, and rollback-safe promotion.
